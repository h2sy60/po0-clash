# 0015. 用分享链接导入单个节点

- 状态：已采纳
- 日期：2026-10-22

## 背景

维护者希望像 v2rayN / v2rayNG 那样，直接把一条条节点的分享链接（`vmess://`、`vless://`、`trojan://`、`ss://`、
`hysteria2://` 等）导入使用，而不是只能导入订阅或 YAML 配置。导入的节点统一放进一个「手动节点」配置，分流沿用维护者
提供的配置模板；单个节点要能删除、重命名。

## 决定

- **解析交给内核。** 新增内核方法 `convertShareLinks`（`core/share_links.go`），直接调用 mihomo 自带的
  `common/convert.ConvertsV2Ray`，返回 mihomo 的代理映射列表。识别不了的行会被跳过，一条都识别不了时返回空列表。
  Dart 侧不重写各协议的解析。
- **节点配置由模板生成。** 模板是 `assets/data/node_profile_template.yaml`（维护者提供的配置，去掉了两条只对维护者个人有用的直连规则）。
  生成时节点写进 `proxies`；代理组里的 `__PROXY_NODES__` / `__PROXY_PROVIDERS__` 占位符这样处理：
  - 组已开启 `include-all`、`include-all-proxies`（或 `include-all-providers`）时直接去掉占位符。mihomo 本来就会把
    全部节点 / 代理集合纳入，再展开一遍会重复。
  - 否则把占位符展开成节点名，或者把代理集合名写进 `use`。
  - 组最后一个成员都没有时补一个 `DIRECT`，否则 mihomo 会拒绝整份配置。
- **节点只存在配置文件的 `proxies` 里。** 每次导入、重命名、删除，都先读出 `proxies`，改完后按模板重新生成整份文件，
  再经 `validateConfig` 校验后保存。几次修改按顺序串行执行。直接改配置文件的其他内容，会在下次增删改节点时被覆盖；
  调整规则请用「覆写」，覆写按配置单独保存，不受影响。
- **「手动节点」配置的 ID 存在 `Config.nodeProfileId`。** 对应的配置被删除后视为不存在，下次导入时重新创建。
- **生成的 YAML 给所有字符串加双引号。** 节点名、密码、UUID 都是用户内容；不加引号的话，`!HK`、`+1`、`True`、
  `2024-01-01` 这类值会被解析成标签、数字、布尔值或日期。
- **导入去重。** 除名称外参数完全相同的节点视为重复，跳过。名称如果和已有节点、模板里的代理组或内置策略（`DIRECT`、
  `REJECT`、`GLOBAL` 等）重复，就在后面追加「 2」「 3」。没有名称的节点用 `地址:端口` 命名。
- **重命名、删除时同步已选节点。** 重命名会把该配置 `selectedMap` 里指向旧名称的选择改成新名称；删除会移除指向它的选择。
- **入口。**
  - 添加配置面板新增「分享链接」，可一次粘贴多条，也可粘贴 base64 订阅内容。
  - 扫码（手机摄像头、桌面端选图片）也放行分享链接，经 `addProfileFormURL` 转到节点导入。单独一条 http(s) 链接仍按
    订阅处理。
  - 「手动节点」配置的菜单里有「节点」页，可以从剪贴板导入、扫码、粘贴导入，也可以重命名、删除节点。
- **分享链接含有凭据。** Dart 侧调用 `convertShareLinks` 时绕开会记录参数的 `_invokeMethod`。

## 后果

- 支持哪些分享链接和 mihomo 内核保持一致；内核升级带来的新协议无需改 Dart 就能用。
- mihomo 的转换器在单行 vless / vmess 链接解析失败时，会把整行写进内核的 warning 日志。不改 mihomo
  （见 [goal.md](../goal.md) 非目标），接受这一点。
- 「手动节点」配置只能是「模板 + 节点」的形式；需要完全自定义时，另建本地配置。
- 模板随应用一起更新：升级后，下一次增删改节点就会按新模板重写这份配置。
