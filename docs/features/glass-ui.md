# 前端界面

po0-clash 的现有页面按 [FlClash v0.9.1](https://github.com/chen08209/FlClash/releases/tag/v0.9.1) 的标准外观同步，
源码基准为 `8d4f9744948751f1273fe871e1d05276fac09b0e`。白名单和手动节点是本分支独有页面，沿用同一套组件。
各平台继续使用 `material_ui`，平台差异只影响功能可用性和窗口控制。

本文件保留原路径以兼容已有链接。此前的简洁界面见 [ADR 0016](../adr/0016-material3-performance.md)，
液态玻璃实验见 [ADR 0010](../adr/0010-liquid-glass.md)。本轮同步标准外观，继续使用不透明表面。

## 视觉与组件

- 采用上游的 Dynamic Type 字阶、连续圆角和线形图标；实现分别在 `lib/common/typography.dart`、`shape.dart` 和 `lib/widgets/glyphs/`。
- 主题使用用户种子色生成的 `ColorScheme`，页面、卡片、嵌套块逐层区分；深色表面逐层变亮，纯黑设置保留。
- 普通内容卡片使用 16～20 dp 连续圆角，弹窗 34 dp，首页卡片桌面 32 dp / 手机 34 dp；颜色生成、阴影和图表实现沿用上游。
- 选中的代理显示勾选标记，URLTest / Fallback 固定节点使用图钉标记；它们分别表示实际出口和用户偏好。
- 代理分组使用横向芯片，可滑动、自动跟随选中项，并通过更多菜单进入远处的分组。长列表仅构建可见芯片。
- 设置、白名单、手动节点共用表面、工具栏、图标和模态样式，所有按钮保留可访问名称。

## 操作结构

| 窗口宽度 | 布局 |
|---|---|
| < 600 dp | 胶囊底栏位于页面下方，内容和浮动按钮不被覆盖 |
| 600～839 dp | 紧凑图标导航 |
| ≥ 840 dp | 文字侧栏，首页采用响应式卡片布局 |

首页直接移植上游 `lib/views/dashboard/` 的密度规则、四列布局、卡片、出站模式、路由开关、局域网与流量组件。
出口卡保留花形启停按钮、背景装饰、国家标记、运行时间及出口类型 / 组织信息；IP 信息查询沿用上游实现。
手机将上下行放在同一张流量卡，桌面将它们拆为独立速率卡。宽高充足时，下方显示连接 / 请求表和代理分组；空间不足时使用摘要卡。
白名单摘要是本分支额外卡片。手机卡片可通过编辑按钮重新排序，并保存顺序。
连接和请求页面在内容区达到 900 dp 时显示可排序表格，较窄时使用原有详情列表；表格虚拟化行，保留搜索、详情和连接关闭操作。

桌面 TUN / 系统代理仍遵循 [ADR 0011](../adr/0011-exclusive-desktop-route.md)，加白总开关仍遵循
[ADR 0014](../adr/0014-unified-whitelist.md)。启停、加白和节点导入继续通过原有 provider / action 完成。

## 刷新与性能

- Core 不可用、隐藏窗口或离开首页时停止纯 UI 统计；macOS 开启托盘网速时继续采样。恢复时显示最新数据，不重启代理或清零 Core 计数。
- 不可见页面与被禁用的 TickerMode 会停止页面轮询；流量图对未变化的采样不重新启动动画，并使用独立重绘边界。
- 导航图标与分段选择尊重系统减少动态效果设置；没有空闲时持续运行的装饰动画。
- 白名单调度独立于界面可见性；Android 亮灭屏、ggy 11 秒间隔和网络变化处理保持原有语义。
- 节点选中标记在保存的节点已被移除时回退到 Core 当前出口；首次导入尚无运行时选择时，保留订阅原始顺序的默认节点，列表排序不改变默认值，也不会把自动选择保存成固定偏好。
- 节点列表的 Core 响应只传递名称、类型及分组所需的成员、当前出口、测速地址、可见性和图标；延迟历史与协议详情不再随列表重复传输。
  同一节点在多个分组中共享解析后的不可变对象；出口解析按节点名索引并在当前快照内复用结果，延迟排序预先计算排序键。
- 日志与请求使用环形缓冲区，写满后以常数时间淘汰最旧记录；保留记录上限、到达通知、不可变快照和暂停滚动时的历史锚点。
  日志 / 请求页面在切页、禁用 TickerMode、隐藏窗口或进入后台后停止刷新，事件继续写入缓冲区，恢复可见时合并更新一次。
  没有筛选条件时直接使用已有列表；关键词匹配不再逐条建立临时集合。托盘只读取最后一条流量采样，不为速率标题复制整个采样列表。
- macOS / Linux 的桌面 IPC 使用系统就绪通知等待接入和数据，空闲时不再每 20 / 50 毫秒唤醒；停止服务和发送失败通过独立唤醒通道中断等待。
  Windows 命名管道保留现有等待方式。消息分批复用缓冲区，发送完成立即清除对象引用；请求事件只持有展示信息和实时计数，不因排队延长连接及传输缓冲区的存活时间。
  Android 主动释放内存时只触发一次完整 GC，仍清理代理缓存并归还空闲内存。
- 事件 JSON 的编码缓冲由单个批处理线程复用，最多保留 256 KiB，超大批次发送后丢弃该缓冲；编码完成立即清除事件对象引用。
  桌面普通日志通过原有事件通道传递，停止重复写入无人消费的 stdout；错误与致命诊断写入宿主捕获的 stderr。
  Core 进程设置 `PO0CLASH_CORE_DEBUG=1` 时，stderr 额外输出完整调试日志。
- 日志、请求、测速与地理数据更新使用固定结构的事件编码，避免逐字段反射与重复 JSON 转换；未知载荷回退到标准编码器。
  输出与标准 JSON 逐字比对，保留全部字段、空值、端口字符串、转义及时间验证；上游字段变更会触发契约测试。
  桌面在 UTF-8 字节上直接解析 JSON，复用已匹配类型的 Map；Core 和 Android 事件分发缓存监听器快照，注册变更从下一条事件生效。
  同一事件的不可变模型只解析一次并供监听器共享，继续隔离单个监听器异常。

## 图标与身份

应用与托盘继续使用 P / 斜杠零标志，源文件位于 `assets_source/images/icon/`，由 `tool/generate_app_icons.sh` 生成。
前端同步不会改变应用 ID、进程名或已安装应用的数据目录。
